# Listoire code review

Reviewed commit `c09123e` (detached worktree `Listoire-review`), 2026-11-09. Report only: no tracked
file was changed. Build output generated to verify the app (`public/stories/`, `.fallow/fixtures/`,
both git-ignored and absent before) was removed afterwards.

---

## 1. Executive summary

**Overall quality: good core, weak edges.** The domain layer is the strongest part. It is
genuinely well designed:

- `StoryDirector` (story-runtime/director.ts) owns progression, commits a coherent
  Ink + character + game + RNG snapshot before presenting, rolls Ink back on failure, and guards
  stale clicks with `occurrenceId`.
- The rules engine (`features/rules`) is pure, deterministic (xorshift with rejection sampling),
  and anti-save-scum (`pendingCheck.origin` restores the RNG on Back).
- Zod contracts are strict at every trust boundary: bundles, saves, archives, uploads, GLB, data
  URLs. There is no `innerHTML`, no `eval`, and no `localStorage`. Typography markup is parsed
  from an allowlist into text spans, never HTML.
- Unit tests for the runtime use real Ink and fake IndexedDB, and test failure paths (rollback,
  conflicts, retries). They test behaviour, not the implementation.
- Fallow: 0 dead code, 0 clone groups, and the architecture boundaries are enforced.

**Where the AI authorship shows**:

- The UI and editor layers re-implement the same small things many times:
  - asset URLs built by hand in 11 places;
  - default volumes copied in 4 places;
  - SHA-256 hex encoding written 3 times;
  - about 60 inline `french ? … : …` strings, even though i18next is already in the project.
- Story-specific migration code (release strings, French titles, encounter IDs) lives in
  `contracts/` and `editor/` and runs on the reader's path.
- The docs and the end-to-end tests describe a different story ("The House That Remembered")
  from the one that ships ("L'École des choses impossibles / Orée").

Fallow scores the project 95/100. That number measures structure. It does not catch these
behavioural gaps.

**Top concerns**

1. **A fresh checkout cannot build, and CI cannot pass.** All 527 catalogue images come from
   `.fallow/library-cache/`, which is git-ignored. On top of that, 24 e2e tests (×4 browsers)
   target the old story and fail. There is effectively no browser regression safety net.
2. **The editor silently loses media configuration.** Deleting or cutting a `// @media` comment
   line deletes that image and its cues. Pasting the line back does not restore them (verified
   with the real project).
3. **Editor performance and storage do not scale.** On every keystroke, the whole project is
   serialised twice for undo history. Each autosave does 2 IndexedDB writes; each write
   re-validates 31 full project copies and re-hashes every uploaded file.
4. **French readers see English in the game, combat and character UI**, including messages
   generated by the rules engine.
5. **Uploaded media breaks wherever a URL is built by hand** instead of going through
   `resolveAsset`. Some code paths also ignore `BASE_URL`.

## 2. Top 15 issues (ranked by impact)

Effort: **S** < 2 h · **M** ≈ ½–1 day · **L** > 1 day.

### 1. A fresh checkout cannot build; CI's `npm run check` fails — S/M
- **Where:** `tools/build-editor-project.ts:172-179` reads `entry.optimizedPath`. All 527 entries
  in `assets/catalog/curated.json` point to `.fallow/library-cache/…`, which `.gitignore:7`
  ignores. CI runs `npm run check` (`.github/workflows/quality.yml`), which runs `stories:build`.
- **What:** `node tools/build-story.ts` fails with `ENOENT …/.fallow/library-cache/images/sketch.curly-haired-woman-standing-001.webp`
  (verified). Without `public/stories/house`, `presentation-validation.test.ts` and
  `magic.test.ts` also fail. `npm run dev` fails the same way.
- **Why it matters:** CI is red for structural reasons, and nobody but the original machine can
  build. README:150 ("Prebuilt selected derivatives in `stories/house/media/` let normal
  development/CI build") is false: that folder holds 115 files, but the referenced `sketch.*`
  images are not among them.
- **Fix:** Commit the *referenced* optimised derivatives under `stories/house/media/` and make
  `assetSource` fall back to them. Or make the build skip missing-but-unpublished library
  entries and fail only on assets the story references. Add a CI step that runs the build from
  a clean checkout.

### 2. The e2e suite tests a story that no longer ships — M
- **Where:** `tests/e2e/house.spec.ts:8`, `presentation.spec.ts:45`, `reader-polish.spec.ts:9`
  ("The Girl in the Photograph"); `reader.spec.ts:184` and `editor.spec.ts:19,379` ("The House
  That Remembered"). `house.spec.ts` also expects a "Reset view" button that no longer exists
  (its i18n key `resetView` is unused).
- **What:** REFACTOR_LOG reports 24 failures per browser (98 in total), identical before and
  after refactoring.
- **Why it matters:** The browser flows that matter most (photograph, branches, character,
  reload restore) are not tested at all. Every UI regression in this report would pass CI.
- **Fix:** Point these specs at the published story using stable IDs (`data-block`, segment IDs)
  instead of prose headings. Or ship a small dedicated e2e fixture story and serve it in the
  tests, so story edits don't break them.

### 3. Cutting or deleting a `// @media` line destroys that media's configuration — S
- **Where:** `src/features/editor/media-script.ts:6-37` (`editMediaScript`), called on every
  Ace change (`editor-actions.ts:65-75`).
- **What:** When a reference line disappears from the script, the media block and all events
  targeting it are deleted from `configuration.scenes`. Pasting the line back keeps the comment,
  but the block is not restored (verified on `matin-ville/matin-ville.illustration`: 2 refs →
  0 → 0). The same happens when a passage is moved by cut and paste.
- **Why it matters:** Silent data loss in the normal editing flow. Recovery is only possible via
  undo or History, and only if the author notices.
- **Fix:** Don't treat the comment line as the source of truth. Keep the configuration, show
  orphaned media under "Scene Media" with a "Remove" action, and re-anchor when the line comes
  back. At minimum, reattach on paste from the previous project snapshot. Add a unit test for
  cut, paste and restore.

### 4. Editor undo history and autosave cost scale with project size — M
- **Where:**
  - `project-history.ts:14-24`: `JSON.stringify` of the whole project, twice, on every change.
  - `use-editor-project.ts:60-66`: `refreshDefaultArtwork` and `withMediaReferences` on every
    keystroke.
  - `persistence/editor-store.ts:36-63`: each write parses the previous record, then the new one.
    That is 31 `StoryProjectSchema` parses, each with the `JSON.stringify(…, null, 2)` 8 MB
    refine (`editor-project.ts:83-86`).
  - `writeAndPublish` writes twice per save (`use-editor-project.ts:176,187`).
  - `compileProject` compiles every language twice (`compiler.ts:126-136`, once for
    `structure()` and once for `compileLanguage`).
  - `verifyMediaAssets` re-reads and SHA-256-hashes every uploaded file, up to 50 MB each
    (`asset-validation.ts:13`).
- **Why it matters:** The current project is already 2.3 MB. Typing lag grows with project
  size. One IndexedDB record holds up to 30 full copies (240 MB worst case), which risks hitting
  the quota and producing "Save failed" loops.
- **Fix:**
  - Record history entries as one string per change, not two, and debounce them.
  - Validate the project once, outside `update()`, and don't re-parse stored history (validate
    on read only).
  - Store history checkpoints in separate keys with a byte budget.
  - Compile once and derive `structure()` from the same JSON.
  - Cache upload verification by digest for the session.

### 5. French readers see English in game, combat and character UI — M
- **Where:**
  - **English-only rule messages shown to FR readers:** `rules/combat.ts:19,98,115,124` and
    `rules/actions.ts:110` produce "3 damage dealt · 2 damage received", "Escaped", "Victory",
    "Success". They are displayed at `CombatControls.tsx:83` and `GamePanel.tsx:151`.
  - **Unlocalised labels:** the modal title "Combat" (`GamePanel.tsx:63`) and raw effect IDs
    (`CombatControls.tsx:78`).
  - **About 60 inline ternaries** in `GamePanel`, `CheckRoll`, `CombatActions`,
    `CombatOptionDetails`, `CombatControls`, `Combatant`, `ChoiceList`, `CharacterPanel:361-363,422`,
    `PassageText:132` and `SceneIllustration:259,265`.
  - **Three different locale tests:** `=== "fr"`, `.startsWith("fr")` and a `french` prop.
  - **English on the FR welcome page:** "Story Editor" (`WelcomeScreen.tsx:29-31`) and
    "Open Story Editor" (`ReadingSession.tsx:53`). Verified in the browser.
- **Why it matters:** Bilingual support is a core requirement. Any third language would need
  edits in about 15 files.
- **Fix:**
  - Have the rules return structured results (`{ kind: "damage", dealt, received }`) and format
    them in the UI with `t()`. `lastResult.message` can stay as a debug fallback.
  - Move every inline string into `i18n.ts`, under `game.*` and `combat.*` namespaces.
  - Use `useTranslation()` everywhere and delete the `french` props.

### 6. Uploaded media and non-root deployments break where asset URLs are built by hand — M
- **Where:** 11 hand-built URLs:
  - `CharacterPanel.tsx:404`
  - `SceneIllustration.tsx:291` (depth layers) and `:321` (effect images)
  - `scene-audio.ts:23`
  - `narration-clips.ts:41`
  - `Combatant.tsx:30`
  - `presentation-session.ts:42`
  - `media-store.ts:28`: `/stories/house/` ignores both `BASE_URL` and `storyId`, while
    line 40 of the same file uses both.
  - `media-form.ts:145`
  - `MediaLibrary.tsx:202,267`
  - `IllustrationPreview.tsx:17`

  More hard-coded root paths: `asset-validation.ts:15`, `default-project.ts:8`,
  `ace.ts:60,74,77`, `main.tsx:18,22`, plus `href="/"` and `href="/editor"` links.
- **What:** An uploaded `upload.<digest>.webp` used as a character portrait, a parallax layer or
  an effect image points to a file that is never served, so it shows as a broken image. Any
  deployment under a sub-path breaks the editor, the uploaded-media fallback and the links.
- **Fix:** One `assetUrl(bundle, asset)` helper for static assets. Have every component go
  through `presentation.resolveAsset` or `useAssetSource`. Use a single `appPath()` helper based
  on `import.meta.env.BASE_URL`.

### 7. Rules and content errors are reported as "Your place could not be saved" — S
- **Where:** `director.ts:105` maps every non-`ReaderFailure` to `"storage"`.
  `rules/*.ts` throws plain `Error`s, for example `awardXp` with a negative amount
  (`character.ts:70`), and `validateGameState` errors also arrive here.
  `CheckpointControls.tsx:56` maps a *download* failure to `"storage"` too.
  `CheckRoll.tsx:96,102` says "Could not save" for every failure.
- **Why it matters:** Users are told their save failed when the story content is broken, and
  authors get no signal about the real cause.
- **Fix:** Wrap rule exceptions as `ReaderFailure("content")` in `game-session.ts`. Give the
  backup action its own message. Log the original error in development.

### 8. Authored stories fail if one Ink line takes more than 50 ms — S *(plausible, not reproduced)*
- **Where:** `story-runtime/ink-frame.ts:96-101`: `story.ContinueAsync(50)`, then
  `throw ReaderFailure("content")` if the line isn't complete.
- **What:** In inkjs, `ContinueAsync` is a time budget that you are meant to call again until it
  completes. Every editor-built bundle has `authored: true`. On a slow phone, or on the first
  continue after load (cold JIT), a heavy line can exceed 50 ms and the story shows "This story
  could not be opened".
- **Fix:** Loop `ContinueAsync` until `asyncContinueComplete`, with a total step or time budget
  of a few seconds. Or use `Continue()` with the existing `steps > 200` guard.

### 9. Skipping a cinematic drops pending timers, so delayed images never appear — S
- **Where:** `scene-playback.ts:313-326`. `skipCinematic` calls `clock.clear()`, which also
  clears the timers scheduled by `showMedia()` (`:171-178`) and `startPersistence()` (`:179-188`).
  `mediaIsVisible` (`contracts/presentation.ts:21-28`) ignores `skipMedia`.
- **What:** An image with `show: { kind: "delay" }` that hasn't appeared yet stays hidden until
  the reader clicks the text (`revealRemaining`). Images with `durationMs` never expire. Changing
  the reduced-motion OS setting mid-page triggers the same path (`StoryPlayer.tsx:75`).
- **Fix:** Use separate clocks for "effects" and "layout timers". Or, on skip, publish
  `visibleMedia: mediaIds()` together with `completedBlocks`.

### 10. The Examine button has no keyboard focus indicator — S
- **Where:** `features/reader/reader.css:2033-2036` (`.reader .examine-photo { outline: 0 }`).
  Its specificity (0,2,0) beats the global `button:focus-visible` rule (`app/app.css:41-47`).
- **What:** Verified in Chromium: `:focus-visible` matches, but `outline-style` is `none`. The
  same element with another class shows a solid outline.
- **Fix:** Delete `outline: 0`, or add `.reader .examine-photo:focus-visible { outline: … }`.
  Also check `.reader h1:focus { outline: none }` (`reader.css:122`): it is intentional for
  programmatic focus, but should keep a `:focus-visible` style.

### 11. Uploaded media is re-read and re-hashed on every mount, and the library decodes every image — M
- **Where:**
  - `presentation/use-asset-source.ts:4-38` has no cache. Every mount calls
    `resolveMediaAsset`, which reads IndexedDB, runs SHA-256 over the whole blob (≤ 50 MB) via
    `verifyUploadedMedia`, and creates an object URL. One upload therefore runs once per
    component (figure + illustration + contour) and again on every page.
  - In `MediaLibrary.tsx:65-79` every card calls `VisualPreview`, which calls `useAssetSource`
    and then `image.decode()` (`use-asset-source.ts:21-24`). This defeats `loading="lazy"`, so
    opening the library decodes all 527 images.
- **Fix:** Add a session-level `Map<digest, Promise<url>>` with reference counting in
  `resolveMediaAsset`, verified once per digest. In the library, render a plain
  `<img loading="lazy">` for static assets and use `useAssetSource` only for uploads.

### 12. Editor-only and story-specific code runs inside the reader — M
- **Where:**
  - `app/ReadingSession.tsx:130-140`: the reader first calls `readActiveProject` (editor
    IndexedDB) and compiles the draft in a worker (`compileInWorker`, which cannot be aborted).
  - `features/editor/default-project.ts:18-133`: hard-coded releases (`"oree-1.3.0"`), French
    titles, encounter IDs (`"ysee-training"`) and the name "The paper dragon". It may rewrite
    the editor record twice on reader load.
  - It also uses a raw `fetch("/stories/house/project.json")` (`:8`), which contradicts commit
    `fa6f4d9`'s claim that all runtime fetches go through `sameOriginFetch`.
  - `contracts/artwork-refresh.ts`: a migration hard-coded to one story, placed in the
    zone meant for shared contracts.
- **Why it matters:** It breaks the stated architecture (contracts minimal, editor isolated). A
  reader opening the app runs editor migrations. Any future story inherits "house"-specific
  rewrites.
- **Fix:** Move the migrations into `features/editor/migrations/`, keyed by
  `schemaVersion`/`release` and run only when the editor loads. Have the reader read only a
  `published` record that the editor already wrote. Route the project fetch through
  `sameOriginFetch`.

### 13. Narration and ambience time out too quickly on mobile networks — S
- **Where:** `media/narration-clips.ts:73-77` gives `timeoutMs: 5000` to download clips of up to
  10 MB. `media/audio-manager.ts:290` sets a 4-second `startTimer` that turns any `play()` that
  hasn't resolved yet into `"timeout"`.
- **Why it matters:** On 3G or slow Wi-Fi, narration silently reports "unavailable" and long
  ambience or music tracks are dropped. Mobile compatibility is an explicit requirement.
- **Fix:** Scale the timeout to the clip size (or drop the fixed timeout and rely on the abort
  signal). Use `canplay` and `stalled` events instead of a fixed 4-second start limit.

### 14. The Game editor can produce an invalid project and offers editable "Stable ID" fields — S/M
- **Where:**
  - `editor/game-authoring.ts:19-35`: renaming or removing both starting abilities in the Game
    editor filters `character.abilities` down to `[]`. `CharacterDefinitionSchema` requires at
    least 1, so every autosave then fails with a raw Zod message. Newly added abilities never
    become starting abilities.
  - `GameActionFields.tsx:13-17`, `GameCatalog.tsx:110-114,321-325`: the "Stable ID" inputs are
    free text. Renaming one breaks every `# game:<id>` in the script, every item ability bonus
    and every action reference, and nothing propagates the change.
  - `mergeAction` (`:67`) merges *all* abilities from the source, but only the referenced
    item or encounter.
- **Fix:** Validate in `applyGameConfiguration` (parse the character) and show a clear error.
  Make IDs read-only after creation, or offer a "Rename ID" action that rewrites references in
  the script and the configuration.

### 15. Exporting a project holds every uploaded file in memory as base64 at once — S
- **Where:** `editor/project-archive.ts:16-37` uses `Promise.all` over all uploads, converting
  each to a data URL with `FileReader` (≈ 1.33× its size), then runs
  `JSON.stringify(…, null, 2)` on the whole result. The import side reads the file as one
  string of up to 200 MB (`editor-actions.ts:179-185`).
- **Why it matters:** A few 50 MB videos crash the tab, and the backup is the only way to move
  work between devices (README).
- **Fix:** Export a ZIP or a streamed multipart archive (one entry per upload). At minimum,
  convert uploads one after another and write the output without indentation.

## 4. Maintainability and AI-specific smells

- **Dead or unreachable options**
  - `CharacterSheet`'s `combat` prop is never `true` (the component isn't exported, and its only
    caller omits it). The damage pop-up, the hidden XP and health in combat, and the
    `character-sheet-combat` styles are all dead (`CharacterPanel.tsx:78-106, 370-415`). The
    comment on line 33 describes behaviour that doesn't exist.
  - `Ribbon.tsx:292-297` handles `action === "unavailable"`, which no command uses.
  - `IllustrationMode` offers "Auto Compose (future)" (`ImageComposition.tsx:101`).
  - The `ReactBitsLayer` safety overrides make several schema props useless (see section 3).
- **Unused i18n keys** (13): `chapterOne`, `replayVoice`, `notesHint`, `xpLabel`, `panLeft`,
  `panRight`, `resetView`, `storyNotes`, `quiet`, `storyLabel`, `library`, `welcome.create`,
  `welcome.soon`. FR typos: "sauvegardees sont conservees" (`i18n.ts:163`). STR/DEX/WIL are
  not translated.
- **Misleading names**
  - `storyId: "house"` holds the Orée story; schema, loader and tools hard-code `"house"`
    (`editor-project.ts:38`, `bundle-loader.ts:14,26,42`).
  - `resolveGameAction(…, deferRoll = true)` *rolls immediately*, then marks the check as
    `rolled: true` (`game-session.ts:60-63`). `rollCheck` only matters for legacy saves.
  - `refreshDefaultArtwork(next, latest)` gets the previous draft as its "source"
    (`use-editor-project.ts:62`), which isn't the built project the function expects.
- **Form state sent through the DOM:** `MediaDialog` keeps state in React, serialises it into
  hidden JSON `<input>`s, then reads it back with `FormData` reflection and
  `as unknown as MediaEdit` (`MediaDialog.tsx:206-219`, `ImageComposition.tsx:34`,
  `CinematicFields.tsx:27,47`, `ExaminationFields.tsx:35`). The form mixes controlled and
  uncontrolled inputs, and booleans silently become `false` when their input isn't rendered.
  Use one typed reducer as the form state.
- **Hard-coded catalogue data in UI:** `IllustrationStarters.tsx:5-31`; story-specific cues in
  `tools/magic-direction.ts`; the French and English default titles in `default-project.ts:89-93`.
- **Imperative DOM in React:** `ImageDragStage` assigns `node.onpointermove`
  (`ImageLayers.tsx:141-163`). `tooltips.ts:45-77` runs a `MutationObserver` over the whole
  editor, including Ace's DOM, re-querying every button and label on every mutation and adding
  generic titles such as "Changes take effect when you apply this dialog", which is false for
  fields that apply immediately.
- **Prop drilling** of `PresentationSession` through 12 reader components (REFACTOR_LOG
  "coupling"). A `PresentationContext` would remove it.

## 6. Accessibility

Good: native `<dialog>` with focus restore (`shared/Dialog.tsx`); `aria-live` status lines;
screen-reader copies of text that is revealed letter by letter; a keyboard-operable magnifier;
the heading receives focus on page change; a skip link; tested reduced-motion paths.

Problems:
1. **Missing focus ring** on Examine (issue 10, confirmed). `.reader h1:focus { outline: none }`
   needs a `:focus-visible` style.
2. **Tabs:** the inventory `tabpanel` has `aria-label` set to the raw ID `"objects"` (confirmed
   in FR) and no `aria-controls`/`id` linking. `Ribbon` and `StoryOutline` use `role="tab"`
   without arrow-key navigation or `tabpanel`s. `GameEditor` uses `aria-pressed` for the same
   pattern.
3. **Character stats:** `<div tabIndex=0 title aria-label>` inside `<dl>`
   (`CharacterPanel.tsx:169`). `aria-label` on a role-less div is ignored by several screen
   readers, so the information exists only as a title tooltip. Use visible text or
   `aria-describedby`.
4. **Escape** closes the character sidebar only when the `aside` itself has focus
   (`CharacterPanel.tsx:67-69`). The preferences panel closes on Escape but doesn't return focus
   to its toggle (`ReadingControls.tsx:106-108`).
5. **Language:** French UI with English strings (issue 5) means mixed-language speech without
   `lang` attributes. `Combatant` progress bars are labelled "Opponent"/"Character" but not with
   the name.
6. **Duplicate icons:** inventory and encounters both use "♧" (`CharacterPanel.tsx:14-19`). They
   are `aria-hidden`, but sighted users can't tell them apart.
7. **Editor:** `PanelDivider` has `aria-valuenow` without `aria-valuemin`/`aria-valuemax`.
   `ImageDragStage` is pointer-only (the sliders are an alternative, which is acceptable).
   Generic auto-tooltips add noise.
8. Text paragraphs act as "click to reveal all" (`PassageText.tsx:162`) with no keyboard
   equivalent on the paragraph itself. The toolbar's "Show all text" covers it; make sure it is
   always reachable while the text is revealing.
