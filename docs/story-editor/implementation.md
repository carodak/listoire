# Story Editor implementation

Implemented 2026-11-03 for the attached Story Editor request. Authoring UI is available
only at `/editor`. The landing page links to that route; the existing wide reader
remains the normal reading experience. This report distinguishes working features
from requirements whose assumed runtime does not exist in this repository.

## Use

1. Run `npm run dev` and open `/editor`.
2. Select English or French. Edit the actual Ink script, localized title and settings.
   Switching languages preserves every draft. Additional languages start explicitly
   unreviewed and do not inherit another language's recorded narration.
3. Use Story, Logic, Media, Game and Review ribbons. Game is hidden in Narrative Only.
   Additional Commands contains all ten upstream Inky Web categories and all longer
   examples. Parameter dialogs supplement, rather than restrict, manual Ink.
4. Save is automatic after a 1.2-second editing pause. Manual Save also creates a
   version checkpoint. Drafts survive compiler errors; only a fully validated project
   replaces the browser's published reader content. Missing media prevents publication.
5. Preview opens automatically using the real StoryPlayer, StoryDirector, Ink engine
   and presentation services, with isolated memory saves. The header Preview button
   recompiles and restarts it; the footer can start from the selected Knot or Stitch.
   It docks to the right on desktop and stacks below on small screens. Its header
   keeps only fullscreen and close; the normal reader retains Back, while preview omits it.
   Typing does not restart the running preview. The language selector uses compact codes.
   Keyboard-accessible dividers resize navigation and preview; the script fills the remainder.
6. Export Ink or a complete project JSON backup. To change the checked-in/default story,
   replace `stories/house/project.json` with that backup and run `npm run build`.
   Video backups include their bytes; ordinary project history retains only hash references.
   Browser autosave does not modify repository files or other devices.

Serve the application with an SPA fallback for `/editor`. `/editor/` normalizes to
`/editor`; asset paths and the requested authoring route assume origin-root hosting.
No publishing service, accounts, remote deployment or multi-story manager was added.

## Story migration

`stories/house/project.json` is now the active editable house build input. It contains
the complete existing English and French scripts and their entire scene, block,
effect, examination, panel, character, asset and narration configurations. Its stable
ID remains `house`. The original book title was "The House That Remembered" and the
opening scene was "The Girl in the Photograph"; both are preserved and editable.

`original-project.json` is the pre-migration backup; `migration-inventory.json` records
source digests, passage IDs and media references. The old `.ink` files and
`metadata.json` remain available as historical references, but the house builder no
longer reads them. There are no independently maintained active React paragraphs.

Migration tests compare all paragraphs, choices, destinations, facts and checkpoint
round trips for 16 paths per language: all three binary choices, each with and without
photograph examination. They also compare complete audiovisual metadata and assets.
The compiled Ink digests are unchanged. Existing optimized media files are referenced,
not duplicated into a second source library.

The initial saved profile is unchanged: 6/6 HP, STR/DEX/WIL generated by the existing
3d6 creator, and two informational Rank 1 abilities. Character initialization and
randomness stay in application/domain composition, outside React event handlers.

## Reuse and ownership

| Area                  | Implementation                                                                                                                                              |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Editing               | Pinned Inky Web Ace editor, Ink syntax mode, search/replace extension and complete command definitions/examples                                             |
| Undo/redo             | Upstream Ace UndoManager stores one project-wide transaction stream, including metadata and translations; typing is coalesced and capped at 30 transactions |
| Compilation           | Existing installed `inkjs/full`, isolated in short-lived workers with a 15-second timeout                                                                   |
| Progression           | Existing InkNarrativeEngine behind NarrativeEngine and StoryDirector; authored untagged Ink also works                                                      |
| Preview               | Existing `createPlayer` and `StoryPlayer`, with isolated SaveManager storage                                                                                |
| Presentation          | Existing PresentationSession, EffectsEngine, React Bits registry, AudioManager and NarrationManager                                                         |
| Authoring persistence | `listoire-editor/projects`, with schema validation, serialized writes and optimistic revision checks                                                        |
| Reader persistence    | Existing `listoire/records`; editor versions never overwrite gameplay checkpoints                                                                           |
| Source builds         | `build-story.ts` retains foundation fixtures; `build-editor-project.ts` compiles the house project and verifies licensed media bytes                        |

Native Ink remains editable. Ribbon insertion uses Ace's insertion primitive and the
upstream examples. Structure commands share IDs and safe source coordinates across
translations; new counterpart text is explicitly marked for review. Insertion inside
different translated sentences is refused rather than guessing a corresponding cursor.
Manual structural edits remain possible in each script. Compilation compares executable
Ink structure, logic literals and stable tags, while ignoring translated output text;
structural drift blocks publication until the languages are aligned. This is not an
automatic translator or a general Ink source-to-source rewriting engine.

New untagged paragraphs retain their Ink order around existing illustration anchors.
Author-authored Ink execution also has a per-continuation time limit so a narrative
loop cannot indefinitely freeze the preview. Runtime failures remain reader failures,
not gameplay mutations.

## Media and narration

The selected Cover image supplies the right-hand cinematic artwork through a
validated optional bundle `cover` asset reference. The default bilingual project
uses three original generated shadow-art illustrations, with provenance and hashes
in the curated catalog. Existing default artwork identities are refreshed without
replacing authored text or custom covers. The photograph's hotspot now matches its
visible upstairs window. Ink and saved progression remain unchanged.
See [shadow-art.md](shadow-art.md) for generation prompts, migration and checks.

Image properties include existing placements, a background placement, width, alignment,
fit/crop, alt text, caption, page/segment/delayed visibility and optional persistence.
Type labels are Image Inline, Image Wide, Image Background and Cinematic Image.
Position defaults to the command's actual executed location in Ink; X/Y percentages
can override its visual offset. Compilation translates image/video comments into
non-visible Ink media tags, and resolved frame anchors retain their position through saves.
This also works for untagged paragraphs and conditional branches. Initial references
are inserted at the existing scene-block positions, preserving the original layout.
Scene and event IDs remain stable. All existing images and cues receive visible
`// @media scene/id` references without changing compiled Ink. The sidebar has Files,
Story Outline (Knots and Stitches) and Scene Media tabs. Hovering a media entry highlights
its reference; clicking reopens its properties. Deleting a reference removes its
configuration and dependent image cues; project undo restores the complete change.
Native animations target Scene, Scene Transition, an image or a text segment; options
are restricted by target. Scene Transition currently supports a departure fade-out.
Sound/music commands use existing channels, volume, looping,
fade/crossfade and stop operations. Complete scene/effect parameters remain available
through schema-validated Scene Properties and All story properties JSON dialogs.

Browse media library opens a gallery with image/audio previews and its own search
(names, descriptions and catalog facets), category, theme and narrative usage filters.
It searches the vetted optimized story assets. It does not publish the thousands of unverified catalog
entries or redistribute the local source library. The builder still verifies provider
rights, image origin, file hashes and identity consistency across languages. Uploaded
recording rights are an author attestation; they are not provider-verified licenses.

Narration supports Disabled, AI Live, AI Pre-generated and Human Recording settings,
separate model/voice selection, voice allowlists, speed, volume, pitch, temperature,
seed and supported expressiveness/guidance defaults. Nano disables parameters it ignores.
Authors can add named voices using permission-attested MP3/WAV examples (6–30 seconds,
maximum 5 MB, eight profiles per language). This is reference conditioning, not training
new model weights. Custom conditioning is reset before the next built-in voice request.
Preview audio applies speed and volume immediately; generation bakes in pitch while
preserving duration. The exact settings/reference enter cache and clip matching.
Existing verified clips are preferred before requesting generation. Explicit generation
uses the existing local Chatterbox service and exact-text cache, then embeds verified
MP3 bytes and their metadata in the project. Human MP3s are also included in backups;
an optional duration override permits authoring when browser MP3 metadata decoding is
unavailable. Every new clip remains a **preview**; no listening approval is fabricated.

The new loopback-only `/api/narration/editor-preview` accepts bounded unsaved authored
text and bounded voice profiles/settings (7 MB request cap). Audio references are decoded
with forced MP3/WAV demuxers, local-only protocols and subprocess timeouts. The original
endpoint retains its exported-text allowlist and 20 KB request cap.
Local generation still requires the existing service, models and development proxy;
no public inference backend was added. EN uses Nano, FR uses Multilingual V3, within
the existing voice configuration. Dynamic Ink text should be checked in Preview; the
manual spoken-text field can represent the resolved variant for a chosen test state.
Batch `narration:export` uses the active project, and compatible generated publication
clips can be merged without replacing approved or embedded author recordings.

Videos use the same ordered media blocks, type/width/position/timing forms and reader.
MP4/WebM uploads require a rights attestation and are capped at 50 MB each. Verified
immutable binary bytes live in `listoire-media/files`; drafts and undo/history retain
small identities. Complete JSON archives embed those bytes on export and verify their
hashes before restoring them. Uploaded media rights remain author-attested, distinct
from verified library-provider rights. Browser codecs and autoplay rules still apply;
videos have playback controls and follow presentation pause/resume/cancellation.
On browsers without a suitable metadata decoder, authors can supply a duration;
voice-reference duration is still checked by FFprobe before synthesis. MP4/WebM
container headers and hashes are verified even when a duration override is supplied.
Windows WebKit rejects IndexedDB Blob writes, so the store persists ArrayBuffer bytes
and reconstructs playback Blobs; older Blob records remain readable.
Fullscreen video sequences are bounded to three minutes and remain skippable.

Camera/atmosphere/depth presets, reduced motion and optional page turns are described
in [cinematic-effects.md](cinematic-effects.md). No animation dependency was added.

Page Replay restarts text, narration and page-local presentation without advancing Ink
or re-rolling a character. Back restores the earlier coherent checkpoint and restarts
presentation. Back history is capped at 100 pages in the current reading session.
The same background track persists across authored pages until changed/stopped or
completed; page sounds and effects are canceled and restarted.

## Explicit limits

- The specification assumes an inventory/check/XP/combat engine that this repository
  does not contain. The Game ribbon exposes existing character configuration only;
  unavailable operations are disabled with explanations, and With Combat is disabled.
  No duplicate inventory, combat formulas, asynchronous action executor or invented
  game-result commands were added. Consequently the complete combat/game acceptance
  criteria cannot be met by reusing the currently installed application.
- Advanced existing effect parameters and localized media overrides use validated JSON
  properties where there is no dedicated form. Generic audio-target animation loops,
  arbitrary providers/models and character/dialogue voice-routing executors were not
  invented; playback uses the existing runtime's supported operations.
- UI localization remains English/French. Additional story languages are editable and
  previewable; they need reviewed translations and suitable recorded/device narration.
- Project metadata is capped at 8 MB; archives containing video bytes can be imported
  up to 200 MB. Human MP3 and voice-example uploads are capped at 5 MB; videos at 50 MB.
  Embedded recordings favor a self-contained backup for this small book. A separate
  blob archive is the upgrade point for larger audio projects. Browser storage quotas
  still apply; failed writes keep dirty state and report errors.
- Reader Ink changes can make an existing gameplay save incompatible. Its original
  backup/restart recovery flow is preserved; editor saving never silently discards it.
